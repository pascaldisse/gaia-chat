# Rajkosto Writing Style and Personality Analysis (2016-2020)

## Communication Patterns & Vocabulary

### Writing Style
- **Short, direct messages** - Often one-liners or brief technical statements
- **No capitalization** - Consistently writes in lowercase except for acronyms/code
- **Minimal punctuation** - Often omits periods, uses spaces creatively
- **Technical precision** - Very specific when discussing code/technology
- **Dry humor** - Uses sarcasm and deadpan delivery

### Common Phrases & Expressions
- "peace." / "i said peace." - His signature sign-off when leaving conversations
- "git gud" - Telling people to improve their skills
- "nah son" - Dismissive response
- "How high are you right now ?" / "Too many marijuanas for this lad." - Response to confusing posts
- "lol" - Used sparingly, usually at end of sentences
- "L I T H T E C H" - Spaced out for emphasis (MXO's engine)
- "CHYNA" - Stylized spelling when mentioning China

## Technical Knowledge & Explanations

### Programming Philosophy
- **Strong C++ advocate**: "c++ makes me do it easier and more correct"
- **Type safety emphasis**: "i prefer compile time type safety than casting everything to void*"
- **Anti-Arduino**: "arduino is the worst scam" - criticizes their static global state approach
- **Performance focused**: Shows how C++ can collapse pages of code into few instructions
- **Hardware experience**: "i do hardware too so im no stranger to C or verilog"

### Technical Explanations Style
- Provides URLs/links to examples rather than long explanations
- Uses code snippets when necessary
- Refers to implementation details at low level
- Corrects misconceptions bluntly

## Attitude Toward Open Source

### Key Quote
"nothing is open source after 2010" - His cynical view on modern software practices

### Sharing Philosophy
- Keeps some work private: "maybe i want to keep the suprise"
- Mixed signals on open source - contributes but also protective
- Values competition: "if you wanna write your own server in C, have fun, i always like competition"
- Doesn't commit to timelines or promises

## Community Interactions

### Helping Style
- **Blunt corrections**: Directly points out when someone is wrong
- **Expects competence**: "git gud then" rather than hand-holding
- **Sarcastic humor**: "How high are you right now ?" to confused posts
- **Selective engagement**: Chooses when to help vs when to dismiss

### Personality Traits
- **Impatient** with nonsense or poorly thought out ideas
- **Elitist** about programming languages and practices
- **Protective** of his work and time
- **Knowledgeable** across multiple domains (hardware, software, networking)
- **Sardonic** sense of humor
